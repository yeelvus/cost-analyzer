# 全过程多项目成本分析看板 — 诊断与设计说明

> 基于 `01成本统计` 目录与现有 `Desktop/code` 流水线梳理（2026-07-16）  
> 目标：从 **预算 → 责任成本 → 过程实际 → 预估闭环 → 结算/完工** 做多项目统一看板

---

## 一、你现在的成本统计体系（现状地图）

### 1.1 数据分层（已经很完整）

| 层 | 目录 | 作用 |
|----|------|------|
| 主数据 | `0_项目基本信息情况/` | 项目编码、状态、经理、工期 |
| 预算 | `3_预算部分/`（广联达人材机） | 投标/预算基准：人/材/机结构 |
| 责任成本 | `3.1_责任成本/` | 目标成本约束（约 20+ 项目有 std） |
| 过程采集 | `2_成本统计收集/`（项目月报 xlsm） | 项目自报：已发生 + 后续预估 |
| 过程台账 | `9采购 / 10机具 / 11人工 / 9.1商混 / 12财务` | 部门客观流水 → std → sum |
| 合同 | `5_合同管理 / 5.1_分包合同` | 总包/分包合同与签证 |
| 报送管理层 | `1_成本报公司/` | **经营口径**最完整：责任成本、已发生、预估、毛利率、完成比例 |
| 中央聚合 | `项目统计数据汇总_全月份.xlsx` | 多源 join 的 master 宽表 |
| 输出 | `18_output/` + `Z_report/` | 索引、按状态/经理拆分、专项 HTML |

流水线心智模型（你已在 `WORKFLOW.md` 写清）：

```text
各部门 raw → 标准化 std/sum
项目月报 xlsm 刮取 ──┐
                     ├─→ master 全月份宽表 → 各类 HTML/Excel 报告
领域汇总 join ───────┘
```

### 1.2 全过程应串起来的五段链

```text
① 预算（广联达人材机）
   ↓ 对比
② 责任成本 / 投标毛利（目标）
   ↓ 对比
③ 过程实际（采购+人工+机具+商混+分包付款…）
   ↓ 叠加
④ 后续预估（未完工程） → 预计总成本 / 预计毛利
   ↓ 闭环
⑤ 业主结算 / 完工分类（D1~D4）→ 最终毛利确认
```

**管理问题不是缺数据，而是五段链没有在一张「决策面」上对齐。**

## 二、关键诊断：能力很强，但「决策面」断点明显

### 2.1 已有能力（优势）

1. **多源双轨**：项目自报 + 部门台账，可对账。  
2. **主数据匹配**：`project_name_matcher` + JSON，解决别名问题。  
3. **覆盖面广**：合同、采购、机具、人工、商混、财务付款、责任成本、预算均有。  
4. **已有看板雏形**：  
   - `build_cost_kanban.py`（卡片看板，偏简）  
   - `build_comprehensive_cost_analysis_html.py`（钻取型综合报告）  
   - `预算总汇总项目看板.html`、人工/采购专项 HTML  
5. **报送表口径成熟**：`1_成本报公司` 已有「责任成本 / 已发生 / 预估发生 / 预计毛利率 / 完成比例」，**最接近管理层语言**。

### 2.2 数据质量断点（看板前必须认清）

以 master `项目统计数据汇总_全月份.xlsx` **2026年06月** 抽样（约 13 个项目）：

| 字段 | 空/零占比 | 影响 |
|------|-----------|------|
| 毛利率 | ~100% | 不能直接用 master 算健康度 |
| 实际已发生金额 | ~100% | 过程进度条断 |
| 后续预估汇总 | ~100% | 全周期闭环断 |
| 采购数据汇总 / 人工费汇总 / 财务分包已付款 | ~100% | 台账 join 未进本月或映射失败 |
| 总包合同额 | 多为 0 | 收入侧失真 |

**对比：** 同月 `1_成本报公司/2026年06月…xlsx` 在建约 **25** 个项目，责任成本、已发生、预估、毛利率、完成比例**可用**。

结论：

> 看板 **主数据源应优先用「报公司表」+「18_output 索引」+「预算金额」**，master 作趋势/对账辅源，并反推修 scraper 与 join。

### 2.3 结构断点（全过程视角）

| 断点 | 表现 | 看板后果 |
|------|------|----------|
| 预算↔过程 | 预算 23 项、币种 CNY/THB 混用；过程多万泰铢 | 无法直接算「预算执行率」 |
| 责任成本覆盖不全 | 有 raw/std 约 20+，新开项目可能滞后 | 无目标线 |
| 状态口径多套 | A/AS/D1–D4 与「在建/已完工」报送双轨 | 组合筛选易乱 |
| 看板碎片化 | 预算看板 / 人工看板 / 采购看板 / 简版卡片 各一份 | 领导看不到一条故事线 |
| 单位不统一 | 泰铢 / 万泰铢 / 人民币 | 合计易错一个数量级 |

### 2.4 管理叙事断点

当前能回答：某月某项目报了多少成本、采购花了多少。  
较难一眼回答：

1. **预算 vs 责任成本 vs 当前预计总成本** 三条线是否失控？  
2. **已发生 / 责任成本** 与 **形象进度** 是否匹配（超前消耗）？  
3. **预计毛利 vs 投标毛利** 侵蚀多少、哪些项目在掉？  
4. 人/材/机哪一类在**相对预算超耗**？  
5. 在建 / 收尾 / 已完工 的 **组合毛利与风险集中度**？

## 三、目标看板：全过程 · 多项目 · 可钻取

### 3.1 产品定位

**一页 Portfolio + 一键项目钻取** 的「成本指挥舱」，服务：

- 运考部月度成本会  
- 项目经理对标  
- 对总部报送前的自检  

输出：`Z_report/全过程成本分析看板_最新.html`（单文件离线可开）

### 3.2 信息架构（四层）

```text
L0 组合层（Portfolio）
   KPI：合同/结算额、责任成本、已发生、预估剩余、组合预计毛利/率、风险项目数
   筛选：状态 / 项目经理 / 月份 / 仅在建
   图表：预计毛利率分布、已发生占比、投标→预计毛利瀑布/散点

L1 项目列表/卡片
   每行：编码、名称、状态、完成%、已发生/责任成本、预计毛利率、
         预算执行提示、预警标签（负毛利/侵蚀/消耗超进度/台账缺口）

L2 项目钻取（点击）
   Tab：
   ① 全周期：预算 → 责任成本 → 已发生 → 预估 → 预计总成本 → 结算/毛利
   ② 结构：人/材/机/分包（台账实际 vs 预算人材机）
   ③ 趋势：master 多月毛利/成本（有数才显示）
   ④ 对账：项目自报 vs 采购/人工/机具/财务 sum（差异红黄灯）

L3 专项外链
   人工 HTML、采购看板、机具报告、预算看板（已有文件）
```

### 3.3 核心指标定义（统一口径，避免吵）

| 指标 | 推荐来源 | 定义 |
|------|----------|------|
| 业主合同额 / 预计结算额 | 报公司 | 收入侧 |
| 责任成本 | 报公司 / 3.1 | 目标成本 |
| 投标毛利 / 率 | 报公司 | 签约基准 |
| 已发生 | 报公司 | 过程实际累计 |
| 预估发生 | 报公司 | 后续未完 |
| 梳理成本（预计总成本） | 报公司 | 已发生+预估（含税差口径按表） |
| 预计毛利 / 率 | 报公司 | 结算 − 梳理成本 |
| 完成比例 | 报公司 | 形象/产值进度（与成本消耗对比） |
| 预算人材机 | 18_output 预算金额 | 结构基准（需换算万泰铢） |
| 台账实际 人/材/机 | 18_output 万元汇总 | 客观发生 |
| 消耗进度 | 计算 | 已发生 / 责任成本 |
| 成本-进度差 | 计算 | 消耗进度 − 完成比例（>15% 预警） |
| 毛利侵蚀 | 计算 | 投标毛利率 − 预计毛利率 |

**单位约定：** 看板默认 **万泰铢**；预算 CNY 项目显示原币 +「未换算」标记，或配置统一汇率后换算。

### 3.4 预警规则（第一版可落地）

| 级别 | 条件 |
|------|------|
| 红 | 预计毛利率 < 0；或毛利侵蚀 > 5pct 且完成比例 > 50% |
| 黄 | 消耗进度 − 完成比例 > 15pct；或 0≤预计毛利率 < 5% |
| 灰 | 无责任成本 / 无预算 / 台账全 0（数据缺口） |
| 绿 | 其余 |

1. 修复 `成本_汇总按月收集成本统计.py` 对 **实际已发生 / 后续预估 / 毛利率** 的刮取。

3. 责任成本 std **全覆盖在建项目**。  
4. 预算统一币种与「万泰铢」对齐。  
5. 修正知识层（WORKFLOW 中的 corrections）继续推进。

## 六、一句话总结

你已经具备 **「工厂级」成本数据产线**，缺的是：

1. **经营主表（报公司）与台账/预算在一张决策面上的对齐**；  
2. **master 关键字段补齐**；  
3. **预算→责任成本→过程→预估→结算** 的统一故事线与预警。

第一版看板先 **信任报公司口径做组合决策**，用 18_output 补「客观台账与预算结构」，用 master 补「时间趋势」——再反推修数据管道，避免「先等完美数据再出看板」。
